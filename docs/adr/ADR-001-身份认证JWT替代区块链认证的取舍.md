# ADR-001: 身份认证采用 JWT 而非每用户区块链身份认证（G6 取舍定稿）

- 状态：已接受（Accepted）｜日期：2026-11-01｜来源：deep-dive 遗留项裁决（用户确认）
- 关联：raw 词汇表「JWT」定义（_raw-extract L437）、开发指南 7.3.3 表与 3.2.2 节、AC-ADM-01

## 背景
原始需求（02 算法创新点 / 03 详细方案）提出「基于区块链的身份认证算法」：
用户上链操作前完成身份认证（仲裁签名方案 / BCCA 区块链证书 / X.509 改进）。

## 决策
采用「**JWT 应用层认证 + 管理员准入审核 + Fabric CA（仅网关管理员身份）**」三层组合，
不实现每用户上链前区块链身份认证。

## 依据
1. raw 词汇表本就定义了 JWT（L437），JWT 并非域外概念；需求正文（03 L523）同样接受
   「用户名密码认证」等常规机制
2. 「上链前身份认证」的可测语义已三层承载：JWT 双 Token + 准入证书签发/吊销
   （EnterpriseAdmission / ReviewerQualification，AC-ADM-01）+ RSA/SM2 数字签名验签（AC-ENT-02）
3. FabricCAService 已实现网关管理员 EC 身份注册（@Profile("fabric")），支撑链网关访问控制
4. 开发指南 7.3.3（L2220）与 3.2.2 节（L2341-2350）已显式登记「部分差异」——本 ADR 将该登记升格为正式决策
5. 每用户 Fabric CA 发证的增量收益不支撑其复杂度（本科目为毕业设计交付物，风险/收益不成比例）

## 后果
- 正面：认证面完整、可验收（AC-ENT-02/AC-ADM-01 均有验收卡）、与 raw 的「准入」语义自洽
- 负面/代价：放弃「去中心化身份」「匿名验证」愿景语义（raw 03 L822-837），已在此留痕
- 后续可选项：如需再对冲，可将 FabricCAService.registerEnrollment() 扩展为按用户 register/enroll
