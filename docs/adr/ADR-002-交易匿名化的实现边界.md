# ADR-002: 交易匿名化定界——检索层匿名 + 存储层真实 ID + 管理员/监管穿透（G7 取舍定稿）

- 状态：已接受（Accepted）｜日期：2026-11-01｜来源：deep-dive 遗留项裁决（用户确认）
- 关联：raw 01 §3.3.2（_raw-extract L142-143）、03 L968、SearchService

## 背景
原始需求：「企业用户仅能检索到匿名交易记录，而管理员用户可查询匿名地址对应的现实用户」
（01 §3.3.2）；03 复述并要求「实行匿名的点对点 P2P 交易」。

## 冮策
需求**可测形态=检索/展示层匿名**，按此实现并在本 ADR 定界：

| 层 | 行为 | 依据 |
|---|---|---|
| 检索/展示层 | 企业/审核员只见「匿名企业-XXXX」（带盐 SHA-256 前 8 位，同企业恒等、不可反推）；管理员/第三方实名穿透 | SearchService（带测试），满足 01 §3.3.2 双向语义 |
| 存储层 | Transaction/AuctionOrder 存真实 user_id | 关系完整性、审计与对账（ChainReconciliationService）依赖真实键 |
| 链上载荷 | tradeDataJson 存真实 sellerId/buyerId | 同上；改哈希将与对账服务耦合，风险>收益 |

## 依据
1. 需求的可验证口径是「检索到匿名记录」+「管理员穿透」，检索层已完整满足且有测试
2. 带盐哈希别名可复现（跨记录恒等），满足「匿名地址对应现实用户」的反向穿透设计
3. 链上载荷匿名化会破坏刚落地的链上对账链路，收益（存储层匿名）非需求硬性要求
4. 监管穿透实名属需求内行为（ThirdPartyController），与匿名检索语义互补而非冲突

## 后果
- 正面：需求双向语义可演示、可测试；对账/审计链路零破坏
- 负面/代价：存储层与链上为明文 ID——接受为审计语义；中和项目展示面未套用同一别名口径（留待后续统一）
- 后续可选项：中和项目（CarbonNeutralProject）展示层统一走 anonymousAlias 机制
