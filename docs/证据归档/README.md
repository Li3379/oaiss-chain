### 1.2 目录职责与管理机制
1. **真实凭证持久化**：本目录专用于存放系统外部发布、镜像推送、远程主机部署与演练回滚的权威执行证据；
2. **自动化门禁联动**：CI 流水线中的 `closure-audit.mjs` 会实时扫描本目录下的所有 `.md` 文件，解析其完成勾选的验收条目；
3. **防伪与防漂移**：禁止虚构勾选未经外部实机执行的条目，确保所有标记已完成的上线闸门具备无可辩驳的证据链。

# 第二章 归档文件分类与命名契约

### 2.1 文件分类与命名规范

**表 2.1.1 证据文件分类与命名规范表**

| 类别划分 | 文件命名模式 | 文件角色 | 门禁处理策略 |
| :--- | :--- | :--- | :--- |
| **骨架模板** | `*模板*.md` 或 `*YYYY-MM-DD*.md` | 初始待填模板 | 门禁仅统计数量，不参与勾选比对 |
| **真实存证** | `[环境]-[日期]-[任务名称].md` | 正式执行记录 | 必须包含有效已勾选验收项 `- [x]` |
| **治理指南** | `README.md` (本文件) | 规范指引 | 门禁排除比对 |

### 2.2 验收条目语法契约 (Checklist Contract)
在归档证据文件中，验收条目必须使用标准 Markdown 复选框语法，且条目文本格式必须严格满足：
```markdown
- [x] {闸门名称} ({范围})
```

> **注意 (Note)**：条目文本 `${闸门} (${范围})` 必须与 `docs/运维部署/上线闸门.md` 表格中的第一列与第二列完全对应。如果勾选了未经定义的条目，`closure-audit.mjs` 会触发 `unknown acceptance item` 警报并阻断构建。

# 第三章 归档与闭环审核操作规程

### 3.1 标准归档操作三步法
1. **复制模板**：在执行远程部署或演练前，复制对应模板并命名为具体日期文件（例如 `2026-10-05-staging-rehearsal.md`）；
2. **填充证据材料**：粘贴控制台输出日志、HTTP 探测结果、容器状态截图或 Git 提交哈希；
3. **完成状态标记**：将对应验证通过的条目从 `- [ ]` 更新为 `- [x]`；
4. **触发本地预检**：在根目录运行门禁核验：
   ```bash
   node scripts/gates/closure-audit.mjs
   ```

> **警告 (Warning)**：如果不存在任何真实的外部归档证据文件，上线闸门中的外部执行项切勿提前标记为“已完成”，否则会因缺乏证据支撑导致 CI 阻断。
