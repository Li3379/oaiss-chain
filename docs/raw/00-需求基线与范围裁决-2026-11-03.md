# 需求基线与范围裁决（2026-11-03）

> **文档性质**：L1 原始需求的**修订版**，用于 GSD 驱动开发。
> **原件保留**：`docs/raw/01~05原始需求与标准规格书.docx` 未改动，作为法律/答辩依据。
> **上位依据**：该 docx 及 `DEV-GUIDE.md §11/§12`；代码事实见 `.planning/codebase/`。
>
> **本文件解决三个问题**：
> 1. 哪些需求已实现、哪些只是"看起来有"、哪些根本没做；
> 2. 哪些已实现的功能**没有需求依据**，应当下线或补进需求；
> 3. 换算出可被 GSD 直接消费的需求条目（ID + 验收判据 + 状态）。

---

## 一、裁决规则

| 规则 | 说明 |
|---|---|
| **R1 有据可依** | 每条需求必须能指向 L1（`docs/raw`）的具体章节；指不到则登记为「增强设计」 |
| **R2 不做半成品** | 状态只有四种：`DONE` / `PARTIAL` / `TODO` / `DROP`。禁止"后端有前端无"的长期悬空 |
| **R3 角色单一事实源** | 权限以 `@PreAuthorize` + `scripts/gates/role-matrix-verify.mjs` 为准，文档服从代码 |
| **R4 真实优先** | Mock / 降级 / 规则引擎必须显式标注，不得对外宣称已具备该能力 |
| **R5 删除留痕** | 下线功能需在 CHANGELOG 写明依据（判例：v1.7.1 删除碳币转账） |
