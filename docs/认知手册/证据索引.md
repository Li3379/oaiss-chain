## 五、缺陷复现记录（P0–P2）

### 缺陷 1 · AI Copilot 三端点 401
```
POST http://localhost:5173/copilot/procurement-advice        -> 401   （前端实际请求路径）
POST http://localhost:8001/copilot/procurement-advice        -> 401   （ML 直连，无密钥头）
POST http://localhost:8001/copilot/procurement-advice + X-ML-Service-Secret: oaiss-ml-shared-secret-key-2026 -> 200 ✅
```
根因链：`api/auction.ts:101` 直接 fetch → Vite 代理 `/copilot → :8001` → ML `require_ml_service_secret` 校验 → 前端不带密钥头 / `.env` 中 `ML_SERVICE_SECRET` 为空 / `MlServiceConfig:60` `if(!secret.isBlank())` 为假 → 401。
旁证：带默认密钥直连 ML 返回 200 且内容优质（采购建议含缺口 200 吨、预估成本 11,640 元、行动清单），**证明模型可用，仅链路未接**。

### 缺陷 2 · `POST /emission/predict` 500
```
POST /api/v1/emission/predict {"enterpriseId":1,"months":6} -> 500 code 1000
```
对照：`POST http://localhost:8001/predict/emission/forecast`（带密钥）→ 200，返回完整 forecast_dates/forecast_emissions。说明 ML 侧正常，问题在后端映射与降级覆盖不全。

### 缺陷 3 · 审核员项目核证空态
```
GET /api/v1/carbon-neutral/pending-verification?page=1&size=10 -> 200, totalElements: 0
GET /api/v1/carbon-neutral/projects?page=1&size=200            -> 200, totalElements: 64, 已核证 15
```
按 verifierId 过滤但种子数据未分配给 reviewer001，导致审核员看到 0 条。

### 缺陷 4 · 信用事件英文原文
数据库/接口返回 `reason` 为 `Carbon report certification reward` / `Carbon report audit rejected: report_17924...`，前端直接展示。源码位置：`CarbonService.java:183, :392` 硬编码英文字符串。

### 缺陷 5 · 引导弹窗重复弹出
27 张截图中绝大多数被「3 步上手[双碳链动]」模态框遮挡，路由切换即重弹。引导状态未持久化。

### 缺陷 6 · 监管端缺"核准上链"入口（2026-10-28 已澄清为非缺陷）
监管端仅 1 页只读监控，这是**有意的制衡设计**。上链已由审核员审核通过时自动触发（方案 A），失败由审核员在 `/auditor/verify/list` 幂等补救；原管理员端 `/admin/verify/list`「认证列表」与审核员页渲染同一组件、功能重复，**已随菜单与路由删除**。以上截图为该页删除前的历史证据。

### 缺陷 7 · 文档漂移
`DEV-GUIDE.md §7` 引用的 7 个活文档路径中，`项目概览/产品说明书.md`、`系统架构.md`、`数据库设计.md`、`代码库导航.md`、`快速上手.md`、`接口参考/后端接口.md`、`质量保证/需求实现测试覆盖矩阵-2026-09-02.md` **均不存在**。
